# DecentralHub — План редизайна платформы (UX/UI)

> Файл для Cursor. Цель: убрать перегруз, спрятать лишнее в меню, сделать «одно главное действие на экран».
> Разбит на 5 блоков — каждый можно скармливать Composer'у отдельно. Порядок важен: блок A задаёт правила для всех остальных.
>
> Тёмная тема и общий стиль (чёрный + циан) остаются — меняем структуру и плотность, а не бренд.

---

## Принципы (применять во всех блоках)

1. **Одно главное действие на экран.** У игрока — «Играть», у хоста — «Подключить агент / Запустить». Всё остальное — вторично и визуально тише.
2. **Progressive disclosure.** Продвинутые настройки и редкие действия — в диалоги, шиты (Sheet), аккордеоны и меню «⋯». На первом экране — только то, что нужно 90% пользователей.
3. **Пустые состояния — это дизайн.** Каждый пустой список показывает: что это, почему пусто, кнопку следующего шага. Никаких голых «пусто».
4. **Никакого dev-мусора в UI.** UUID, тестовые хосты без обложек, англоязычные слаги — либо скрыть, либо человекочитаемо.
5. **Один язык.** Весь UI на русском, включая жанры, статусы, плейсхолдеры. Технические термины (WebRTC, TURN) не показывать игроку вообще.
6. **Не менять API и логику** — только представление. Если для UX нужен новый эндпоинт, отметить в TESTLOG и согласовать отдельно.
7. Компоненты — shadcn/ui из `artifacts/web/src/components/ui/` (Dialog, Sheet, DropdownMenu, Accordion, Tabs уже есть — использовать их, не изобретать).

## БЛОК A — Дизайн-система и каркас

### A.1 Ревизия слоя компонентов
Собрать переиспользуемые куски, которые сейчас копипастятся по страницам: карточка игры, карточка хоста, бейдж статуса (онлайн/оффлайн), бейдж пинга, плашка баланса, empty-state.
- Файлы: `artifacts/web/src/components/` (новые: `game-card.tsx`, `host-card.tsx`, `status-badge.tsx`, `empty-state.tsx`), затем замена дублей на страницах
- Готово: одна и та же карточка игры на лендинге, в каталоге и в библиотеке хоста — один компонент.

### A.2 Единая шкала плотности
Завести стандарт: заголовок страницы (title + 1 строка описания), отступы секций, максимум 2 уровня вложенности карточек. Убрать разнобой размеров шрифтов и отступов между страницами.
- Файлы: `artifacts/web/src/index.css` (токены), выборочно страницы
- Готово: все страницы используют одинаковые заголовки/отступы; нет «своих» размеров на каждой странице.

### A.3 Компонент «Настройки в шите»
Универсальный паттерн: кнопка-шестерёнка → Sheet справа со сгруппированными настройками (Accordion внутри). Будет использоваться в плеере, библиотеке хоста, квотах.
- Файлы: новый `artifacts/web/src/components/settings-sheet.tsx`
- Готово: компонент принимает секции `{title, icon, content}` и рендерит их единообразно.

### A.4 Скелетоны загрузки
Вместо спиннеров на весь экран — скелетоны по форме контента (карточки, строки таблиц).
- Файлы: `artifacts/web/src/components/ui/skeleton.tsx` (есть), применить на games, hosts, wallet, exchange
- Готово: ни одна страница не показывает пустой экран или центральный спиннер дольше мгновения.

## БЛОК B — Путь игрока

### B.1 Лендинг: убрать мусор из «Играй прямо сейчас»
Сейчас полка показывает тестовые хосты с UUID-именами («b07df857-c2a8-…», «chat.deepseek.com») и без обложек. Правила: показывать только хосты с играми из модерированного каталога (есть обложка + человеческое название); максимум 6 карточек; если живых нет — полку скрыть и показать «Хосты появятся в онлайне — загляни в каталог».
- Файлы: `artifacts/web/src/pages/landing.tsx`, возможно фильтр на `artifacts/api-server/src/routes/public.ts`
- Готово: на лендинге нет карточек с UUID и пустыми обложками ни при каком состоянии базы.

### B.2 Каталог игр: фильтры по требованию
Левый сайдбар с 6 группами фильтров (категории, возможности, жанры, соединение, цена) при 2 играх в каталоге — перегруз. Схлопнуть в одну кнопку «Фильтры» (открывает Sheet), сверху оставить только поиск + переключатель «Онлайн». Сайдбар возвращать автоматически, когда игр станет >20.
- Файлы: `artifacts/web/src/pages/games.tsx`
- Готово: каталог = поиск + сетка игр; фильтры в один клик, выбранные показываются чипами над сеткой.

### B.3 Русификация жанров и статусов
«Browser Roguelike», «Metroidvania», «Platformer» → русские названия (словарь-маппинг на фронте: слаг → русское имя). Всё, что не в словаре, показывать капитализированным, но записать в TESTLOG для пополнения.
- Файлы: новый `artifacts/web/src/lib/genre-names.ts`, применить в games.tsx, game-detail.tsx
- Готово: в UI игрока нет английских жанров.

### B.4 Страница игры: иерархия действий
Один главный CTA «Играть» (самый крупный элемент). Выбор хоста — списком с пингом и ценой, свернуть детали хоста (специфика железа) в раскрываемую строку. Кнопки «Уведомить», «Хостить эту игру» — вторичные, справа/ниже.
- Файлы: `artifacts/web/src/pages/game-detail.tsx`
- Готово: с любого состояния страницы понятно, куда жать, за ≤1 секунду взгляда.

### B.5 Плеер: разгрузить HUD
`play.tsx` (2000+ строк) показывает много контролов сразу. Оставить на экране постоянно: видео, пинг, время/баланс, кнопка «Выход». Всё остальное (клипы, геймпад-оверлей, настройки качества, статистика соединения, тарифы) — за одной кнопкой-шестерёнкой в SettingsSheet (A.3) с секциями. Предупреждения (низкий баланс, плохая сеть) — тостами, не постоянными плашками.
- Файлы: `artifacts/web/src/pages/play.tsx` (+ вынести секции шита в отдельные компоненты — файл давно пора резать)
- Готово: во время игры на экране ≤5 постоянных элементов поверх видео; всё остальное в 1 клике.

### B.6 Онбординг первого запуска
Первый заход на «Играть»: короткий оверлей из 3 шагов (выбери игру → выбери хоста → играешь в браузере), показывается один раз (localStorage-флаг).
- Файлы: `artifacts/web/src/pages/games.tsx` или layout, новый компонент
- Готово: новичок понимает модель «игра у хоста, платишь за минуты» без чтения лендинга.

## БЛОК C — Путь хоста

Всё про настройку (токен, привязка ключа, скачивание агента, инструкции) — в отдельную вкладку/шит «Настройка», которая разворачивается автоматически только если агент не подключен.

### C.2 Библиотека: таблица вместо простыни

- Готово: новый хост всегда видит, на каком он шаге и что делать дальше.

### C.4 Браузерный хостинг: пометить как «для теста»
`/host/play` (browser-play) — это отладочный режим. Пометить бейджем «Тестовый режим» и убрать из основной навигации хоста (доступ по прямой ссылке и из раздела настроек).

### D.2 История транзакций: группировка и контекст
Русские подписи типов операций уже есть (kindMeta в wallet-history.tsx) — доделать контекст: показывать название игры в строках списаний («Игровая минута» → «Rogue Fable III — 12 мин игры») и схлопывать минутные списания одной сессии в одну строку с разворотом по клику.

### D.3 Профиль: не пугать пустотой
Сейчас профиль почти пуст, а подпись «Зарегистрируйтесь как хост, чтобы начать пополнять историю» сбивает игрока с толку. ### D.4 Биржа: разделить «мне должны» и «я должен»

- Файлы: `artifacts/web/src/pages/exchange.tsx`

### D.5 Квоты: форма в шаги

- Файлы: `artifacts/web/src/pages/quota-new.tsx`, `artifacts/web/src/pages/quotas.tsx`

## Порядок работ и зависимости

1. **A → всё остальное** (компоненты и паттерны нужны каждому блоку).
2. B, C, D можно делать параллельно после A.
3. E — последним (навигация трогает все страницы, мелочи добиваются по горячим следам).
4. После каждого блока: `pnpm run typecheck` + визуальный проход изменённых страниц + проверить, что игровой цикл (каталог → играть → выход) не сломан.

## Что НЕ делать

- Не менять цветовую схему и логотип.
- Не переписывать страницы с нуля — рефакторить структуру существующих.
- Не трогать `play.tsx` глубже HUD (стриминговая логика хрупкая, менять только слой представления).
- Не удалять функционал «потому что редко используется» — только прятать в меню.
