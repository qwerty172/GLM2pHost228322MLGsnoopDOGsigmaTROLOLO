## ФАЗА 1 — Ядро игрового цикла (стрим + управление)

Цель: игрок реально играет — видит стрим, управляет мышью/клавой/геймпадом, понимает сколько платит.

### 1.1 E2E проверка ввода игрока (мышь + клавиатура)
Убедиться, что цепочка «браузер игрока → DataChannel → агент → SendInput» реально двигает мышь и нажимает клавиши в игре на Windows.
- Формат DataChannel: `{type:"input", kind:"key|mouse|wheel", action:"down|up|move", button:0/1/2, x, y}` (x,y нормализованы 0–1)
- Файлы: `artifacts/web/src/pages/play.tsx` (отправка), `artifacts/host-agent/src/renderer/index.ts` (приём), `artifacts/host-agent/src/main/input-injection.ts` (koffi → user32!SendInput)
- Готово: юнит-тест маппинга координат (нормализованные → пиксели экрана с учётом DPI); ручной тест на Windows-ПК: курсор двигается, WASD работает, клики попадают.

### 1.2 Запоминать вручную выбранное окно захвата
Если хост выбрал окно вручную (auto-match не сработал), сохранять выбор в config.json и при следующем запуске той же игры предлагать его первым.
- Файлы: `artifacts/host-agent/src/renderer/index.ts` (window-picker modal), `artifacts/host-agent/src/main/index.ts` (config persistence)
- Готово: повторный запуск той же игры не показывает пикер, а сразу захватывает сохранённое окно (с fallback на пикер, если окно не найдено).

### 1.3 Виртуальный геймпад → реальный ввод (ViGEm)
Мобильный тач-оверлей уже шлёт `{type:"gamepad", axes, buttons}`, но агент его не инжектит. Подключить ViGEmBus (npm `vigemclient` или koffi-биндинг) и создавать виртуальный Xbox 360 контроллер.
- Файлы: `artifacts/host-agent/src/renderer/index.ts:1163` (заглушка уже есть), `artifacts/host-agent/src/main/input-injection.ts`
- Готово: тач-оверлей на телефоне управляет игрой на ПК хоста; graceful-сообщение, если ViGEmBus-драйвер не установлен.

### 1.4 Утечка токенов в ссылках стриминга (security)
Ссылки вида `/play/:playerToken` попадают в логи, историю браузера, рефереры. Заменить долгоживущий токен в URL на короткоживущий join-код, который обменивается на токен через POST.
- Файлы: `artifacts/api-server/src/routes/sessions.ts`, `artifacts/api-server/src/lib/tokens.ts`, `artifacts/web/src/pages/play.tsx`
- Готово: в URL — одноразовый код с TTL; старые ссылки продолжают работать (redirect с обменом); токен не светится в address bar после загрузки.

### 1.5 HUD: живой баланс + минуты до конца
Игрок во время игры видит: текущий баланс LZT, сколько минут осталось при текущем тарифе, предупреждение за 2 минуты до нуля.
- Файлы: `artifacts/web/src/pages/play.tsx` (HUD уже есть — расширить), `artifacts/api-server/src/routes/wallet.ts`
- Готово: баланс обновляется раз в ~15с; при остатке <2 мин — жёлтая плашка; при нуле — понятное окончание сессии, не молчаливый обрыв.

### 1.6 Точный остаток блочного времени после перезагрузки страницы
Блочные тарифы (10/15/25 мин): после F5 таймер должен показывать реальный остаток, а не сбрасываться.
- Файлы: `artifacts/web/src/pages/play.tsx`, `artifacts/api-server/src/routes/sessions.ts` (block expiry в ответе сессии)
- Готово: F5 в середине блока — таймер продолжается с правильного места.

### 1.7 Защита от двойного списания при reconnect блочной сессии
Reconnect не должен создавать второе списание за тот же блок.
- Файлы: `artifacts/api-server/src/routes/sessions.ts`, `artifacts/api-server/src/lib/economy.ts`
- Готово: идемпотентность по (sessionId, blockIndex); тест: два reclaim подряд → одно списание в ledger.

### 1.8 Правый стик на мобильном оверлее
Добавить правый аналоговый стик (камера) в тач-геймпад.
- Файлы: компонент оверлея в `artifacts/web/src/` (искать по "gamepadOverlay" в play.tsx)
- Готово: два стика, оба шлют axes в DataChannel; редактор раскладки позволяет двигать оба.

### 1.9 Обновление пинг-бейджа раз в минуту
Пинг до хоста в каталоге замеряется один раз — сделать пере-замер каждые 60с, пока игрок на странице.
- Файлы: `artifacts/web/src/pages/hosts.tsx`, `artifacts/web/src/pages/game-detail.tsx`
- Готово: значение пинга живое; нет утечек таймеров при уходе со страницы.

### 1.10 Уведомление «любимая игра снова онлайн»
Игрок жмёт «Уведомить» на офлайн-игре → при появлении хоста тост/браузерное уведомление.
- Файлы: `artifacts/web/src/pages/game-detail.tsx` (кнопка уже есть, показывает тост-заглушку), `artifacts/api-server/src/routes/games.ts`
- Готово: подписка хранится (localStorage + опционально серверная), поллинг раз в минуту, Web Notifications API с разрешением.

## ФАЗА 2 — Хост: агент, библиотека, заработок

Цель: хосту удобно — поставил агент, настроил игры и цены, видит доход.

### 2.1 Подписанный установщик агента (.exe)
Заменить ZIP+start.bat на NSIS-установщик через electron-builder. Сборка в CI (GitHub Actions, windows-latest).
- Файлы: `artifacts/host-agent/electron-builder.yml`, `artifacts/host-agent/build/installer.nsh`, новый `.github/workflows/agent-build.yml`
- Готово: GitHub Action собирает `.exe` артефакт; ZIP-путь остаётся как fallback. Подпись сертификатом — отдельно, когда будет сертификат.

### 2.2 Вход в агент по одноразовому ключу (доделать)
Автологин из конфига уже есть. Доделать первый вход: хост копирует 6-значный код с дашборда → вводит в агент → агент получает токен. Убрать ручное копирование длинного токена.
- Файлы: `artifacts/api-server/src/routes/agentAuth.ts` (уже существует), `artifacts/host-agent/src/renderer/index.ts`, `artifacts/web/src/pages/host/dashboard.tsx`
- Готово: новый хост подключает агент за <30 секунд без копирования токенов.

### 2.3 Отзыв и ротация ключа агента с дашборда
Кнопка «Отозвать ключ» на дашборде → старый агент отваливается, показывается инструкция перепривязки.
- Файлы: `artifacts/api-server/src/routes/hosts.ts`, `artifacts/web/src/pages/host/dashboard.tsx`, `artifacts/host-agent/src/main/api-client.ts` (обработка 401)
- Готово: после отзыва агент показывает «Ключ отозван — получи новый на дашборде», а не бесконечные ошибки.

### 2.4 Активные сессии по каждой игре в библиотеке
В библиотеке хоста у каждой игры — счётчик активных сессий и кнопка «завершить».
- Файлы: `artifacts/web/src/pages/host/` (library page), `artifacts/api-server/src/lib/hostLibrary.ts`
- Готово: хост видит кто играет в какую его игру прямо в библиотеке.

### 2.5 Свои цены по тирам игроков (bronze/silver/gold)
Хост задаёт множители цены для тиров игроков.
- Файлы: `lib/db/src/schema/` (hosts или host_games), `artifacts/api-server/src/lib/tariff.ts`, `artifacts/web/src/pages/host/`
- Готово: цена в каталоге и биллинге учитывает тир игрока; дефолт — без множителей.

### 2.6 Уведомления о модерации заявок на игры
Хост подал игру в каталог → видит на дашборде статус: на модерации / одобрено / отклонено (с причиной).
- Файлы: `artifacts/api-server/src/routes/submissions.ts`, `artifacts/web/src/pages/host/dashboard.tsx`
- Готово: плашка с результатом модерации, отклонение показывает причину.

### 2.7 Валидация обложек игр при загрузке
Проверять: формат (png/jpg/webp), размер ≤2МБ, разрешение ≥300×170, реальный image-mime (не по расширению).
- Файлы: `artifacts/api-server/src/routes/submissions.ts`, `artifacts/api-server/src/routes/storage.ts`
- Готово: мусорные файлы отклоняются с человекочитаемой ошибкой до записи в storage.

### 2.8 Авто-подхват квоты агентом перед сессией
Агент при старте сессии сам подбирает подходящую квоту (по железу) и предлагает хосту подключить её одним кликом.
- Файлы: `artifacts/host-agent/src/renderer/index.ts`, `artifacts/api-server/src/lib/quotaAttach.ts`, `artifacts/api-server/src/lib/quotaEngine.ts`
- Готово: тост в агенте «Найдена квота +X LZT/мин — подключить?»; выбор запоминается на сессию.

### 2.9 Фильтр подходящих квот по железу ПК
В списке квот на дашборде хоста скрывать/помечать те, под которые его ПК не проходит по minSpecs.
- Файлы: `artifacts/web/src/pages/quotas.tsx`, `artifacts/api-server/src/routes/quotas.ts` (сравнение с pcSpecs хоста)
- Готово: неподходящие квоты показаны серым с причиной («нужна RTX 3060+, у тебя GTX 1650»).

### 2.10 VDS-игры отдельной секцией в каталоге
Игры, хостящиеся на VDS платформы, показывать с бейджем «Всегда онлайн» отдельной полкой.
- Файлы: `artifacts/web/src/pages/games.tsx`, `artifacts/api-server/src/routes/games.ts` (флаг isVds в ответе)
- Готово: полка «Всегда онлайн» вверху каталога, VDS-хосты помечены.

## ФАЗА 3 — Экономика и надёжность

Цель: деньги работают сами и безопасно.

### 3.1 Автоматические крипто-выплаты
Pending-выводы обрабатываются воркером автоматически (сейчас руками).
- Файлы: `artifacts/api-server/src/lib/walletAddresses.ts`, новый воркер рядом с `depositWorker.ts`, таблица `withdrawals`
- Готово: вывод уходит без участия админа; при ошибке сети — retry с backoff; статус виден в кошельке.

### 3.2 Депозиты → стабильный USD-кредит
Фиксировать курс на момент депозита, зачислять USD-эквивалент, а не сырую крипту.
- Файлы: `artifacts/api-server/src/lib/depositWorker.ts`, `artifacts/api-server/src/lib/economy.ts`
- Готово: курс пишется в запись депозита; баланс не плавает от волатильности.

### 3.3 Долг и обязательства — в профиле и на бирже
Показать долги (кредиты, «играй в кредит») в профиле и на бирже, но НЕ в кошельке.
- Файлы: `artifacts/web/src/pages/profile.tsx`, `artifacts/web/src/pages/exchange.tsx`, `artifacts/api-server/src/routes/loans.ts`
- Готово: в профиле секция «Обязательства» с суммой, сроком, кнопкой погасить.

### 3.4 «Играй в кредит» по умолчанию + настройка
Новичок без баланса может сразу играть в кредит (до лимита), в настройках можно отключить.
- Файлы: `artifacts/api-server/src/lib/economy.ts`, `artifacts/api-server/src/lib/launchFee.ts`, `artifacts/web/src/pages/profile.tsx`
- Готово: первый запуск игры не требует пополнения; долг виден в профиле (3.3).

### 3.5 История блочных списаний в кошельке
Блочные тарифы отображаются в истории транзакций как одна строка за блок с деталями.
- Файлы: `artifacts/web/src/pages/wallet.tsx`, `artifacts/api-server/src/routes/wallet.ts`
- Готово: строка «Блок 15 мин — Rogue Fable III — 120 LZT» вместо кучи минутных записей.

### 3.6 Защита от брутфорса токенов
Rate-limit + экспоненциальная задержка на перебор токенов (кошелёк, plays, join-коды).
- Файлы: `artifacts/api-server/src/lib/rateLimit.ts`, `artifacts/api-server/src/lib/requestToken.ts`
- Готово: 10 неверных токенов подряд с одного IP → 429 с нарастающим окном; тест подтверждает.

### 3.7 Rate-limit при работе на нескольких серверах
Текущие лимиты in-memory — при масштабировании на 2+ инстансов не работают. Перенести в PostgreSQL (или Redis, если появится).
- Файлы: `artifacts/api-server/src/lib/rateLimit.ts`
- Готово: лимиты общие для всех инстансов; деградация graceful, если хранилище недоступно.

### 3.8 E2E-тест экономики
Один сценарный тест: депозит → игра поминутно → блочный тариф → кредит → погашение → вывод. Проверяет консистентность ledger.
- Файлы: новый `artifacts/api-server/src/__tests__/economy-e2e.test.ts`, `artifacts/api-server/src/lib/economy.ts`
- Готово: `pnpm test` в api-server гоняет сценарий на тестовой БД; сумма всех проводок ledger сходится в ноль.

### 3.9 Частичное финансирование займов на бирже
Кредитор может профинансировать часть заявки; заявка активируется при 100%.
- Файлы: `artifacts/api-server/src/routes/loans.ts`, `artifacts/web/src/pages/exchange.tsx`
- Готово: прогресс-бар финансирования на заявке; несколько кредиторов делят проценты пропорционально.

### 3.10 Начисление процентов + напоминания о сроке займа
Проценты по P2P-займам считаются ежедневно и видны обеим сторонам; за 24ч до срока — уведомление.
- Файлы: `artifacts/api-server/src/lib/interestWorker.ts` (уже существует — расширить), `artifacts/web/src/pages/exchange.tsx`
- Готово: заёмщик видит «накапало X LZT», напоминание приходит тостом при заходе на сайт.

## ФАЗА 4 — Технологические апгрейды (после фаз 1–3)

Цель: поднять качество стриминга и инфраструктуру до уровня «продукт», а не «демо».
Отсортировано по соотношению эффект/сложность.

### 4.1 Relative mouse mode (Pointer Lock) для шутеров
SendInput с абсолютными координатами не работает в играх с относительной мышью (все FPS). Игрок: Pointer Lock API + отправка дельт `{dx,dy}` вместо `{x,y}`. Агент: инжект `MOUSEEVENTF_MOVE` (относительный) вместо абсолютного позиционирования.
- Файлы: `artifacts/web/src/pages/play.tsx`, `artifacts/host-agent/src/main/input-injection.ts`, `artifacts/host-agent/src/renderer/index.ts`
- Готово: в FPS-игре камера крутится мышью плавно, без «прилипания» курсора к краям; переключатель «захват мыши» в HUD игрока.

### 4.2 Тюнинг WebRTC: адаптивное качество + frame pacing
Выжать максимум из текущего стека: `degradationPreference: "maintain-framerate"`, `contentHint: "motion"`, приоритет битрейта, ограничение разрешения при потерях, замер и логирование `getStats()`.
- Файлы: `artifacts/web/src/pages/play.tsx`, `artifacts/web/src/pages/host/browser-play.tsx`, `artifacts/host-agent/src/renderer/index.ts`
- Готово: при деградации канала стрим снижает разрешение, а не фризит; параметры энкодера залогированы.

### 4.3 Метрики качества сессий (getStats-пайплайн)
Обе стороны раз в 10с шлют на API срез WebRTC-статистики: битрейт, RTT, потери, фризы, jitter. Хранить в новой таблице, показывать в админке сводку по сессии.
- Файлы: новая схема `lib/db/src/schema/sessionMetrics.ts`, `artifacts/api-server/src/routes/sessions.ts`, `artifacts/web/src/pages/admin/`
- Готово: по любой сессии виден график качества; жалобу «лагает» можно проверить данными.

### 4.4 Redis: общий rate-limit, pub/sub сигналинга, кэш каталога
Одним подключением закрыть три задачи: лимиты между инстансами (сейчас in-memory), горизонтальное масштабирование сигналинга, кэш `/api/games`.
- Файлы: `artifacts/api-server/src/lib/rateLimit.ts`, `artifacts/api-server/src/lib/signaling.ts`, новый `artifacts/api-server/src/lib/redis.ts`
- Готово: graceful-фоллбек на in-memory, если REDIS_URL не задан; лимиты работают на 2+ инстансах.

### 4.5 Свой TURN-сервер (coturn)
Заменить ExpressTurn на свой coturn с ephemeral-credentials (REST API auth), выдача креденшалов через API с TTL.
- Файлы: `artifacts/api-server/src/routes/public.ts` (GET /public/ice-config, ~строка 455 — здесь выдаётся ICE-конфиг), деплой-конфиг coturn (docker-compose или systemd — в `docs/`)
- Готово: relay-соединения ходят через свой сервер; креденшалы живут ≤1 часа.

### 4.6 CI/CD: GitHub Actions + автообновление агента
Пайплайн: typecheck + тесты на каждый push; сборка `.exe` агента (electron-builder) на тег; автообновление через electron-updater (GitHub Releases как канал).
- Файлы: `.github/workflows/ci.yml`, `.github/workflows/agent-release.yml`, `artifacts/host-agent/electron-builder.yml`
- Готово: тег `agent-v*` → готовый установщик в Releases; агент сам предлагает обновиться.

### 4.7 Транзакционный леджер (outbox-паттерн)
Все денежные операции — строго внутри одной DB-транзакции: проводка + событие в outbox-таблицу. Воркеры читают outbox, а не делают побочные эффекты в момент запроса.
- Файлы: `artifacts/api-server/src/lib/economy.ts`, `lib/db/src/schema/ledger.ts`, новая таблица outbox
- Готово: краш сервера в любой момент не оставляет «полусписаний»; тест с искусственным прерыванием проходит.

### 4.8 Короткоживущие токены сессий (JWT + refresh)
Заменить вечные токены в localStorage на пары access (15 мин) + refresh (30 дней, httpOnly cookie). Старые токены поддерживать переходный период.
- Файлы: `artifacts/api-server/src/lib/tokens.ts`, `artifacts/api-server/src/routes/players.ts`, `artifacts/web/src/lib/`
- Готово: утёкший access-токен бесполезен через 15 минут; UX не меняется (тихий refresh).

### 4.9 (Исследование) Нативный захват + NVENC в агенте
Прототип: DXGI Desktop Duplication + NVENC через нативный модуль (Rust/C++, napi-rs), подача уже кодированного H.264 в WebRTC. ⚠️ encoded-insertable-streams в браузере не рассчитаны на чужой битстрим — спайк должен в первую очередь оценить свой RTP-стек (например, поверх webrtc-rs/libdatachannel в main-процессе Electron). Это недели работы — сначала спайк на 2-3 дня: замерить latency и CPU против текущего desktopCapturer.
- Файлы: новый `artifacts/host-agent/native/` (прототип отдельно от прода)

## Что сознательно НЕ вошло (и почему)

| Задача | Причина |
|---|---|
| Микрофон игрок→хост | Ниша, сложность WebRTC-аудио вверх — после ядра |
| Клипы с аудио, шаринг клипов | Полировка развлечений — после денег |
| Центр уведомлений (колокольчик) | Заменён точечными тостами в 1.10/2.6/3.10 |
| Авто-обновление агента | После подписанного установщика (2.1) |
| Гостевые улучшения | Гостевой вход работает, остальное — полировка |
| Кошелёк: вся история (>100) | Пагинация — техдолг, не блокер |

## Как скармливать Cursor'у

1. Одна фаза = один Composer-план (10 задач).
2. Внутри фазы задачи почти независимы — можно параллелить, кроме: 1.4 до 1.5–1.7 (токены в сессиях), 3.3 до 3.4 (долг в UI).
3. После каждой фазы: `pnpm run typecheck` + прогнать e2e стрима вручную.
4. Агент (host-agent) тестируется только на Windows — задачи 1.1–1.3, 2.1–2.3 требуют реального ПК.
